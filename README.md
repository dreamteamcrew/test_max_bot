# test_max_bot

Тестовый Telegram-бот по мотивам ТЗ резервного канала NV-Clinic (в ТЗ — бот в MAX). Реализована простая часть: подключение врача и пациента по ссылкам и переписка между ними через бота. Режимы резерва, дежурные, эскалация, шифрование и бэкапы не входят.

## Сценарий

1. Администратор: `/doctor_add Смирнова Е. В.` — одноразовая ссылка для врача на 14 дней.
2. Врач открывает ссылку, становится врачом и получает личную ссылку для пациентов.
3. Пациент открывает ссылку врача → «Согласен» (запись в журнал согласий) → ФИО → «Поделиться контактом» (принимается только свой контакт с кнопки).
4. Врачу приходит заявка с кнопками «Подтвердить» / «Отклонить». Не больше 10 заявок на врача.
5. Сообщения пациента приходят врачу с подписью. Врач отвечает через «Ответить»; если пациент один, можно писать без «Ответить».
6. `/stop` у пациента удаляет его данные и пишет отзыв согласия в журнал. Посторонний без ссылки получает только объяснение.

Команды администратора: `/doctor_add`, `/doctors`, `/doctor_remove ID`, `/status`. Врача: `/newlink`, `/patients`. Пациента: `/stop`. Всем: `/myid`.

Текст переписки бот не хранит, только связку «ID сообщения у врача → пациент», чтобы работало «Ответить». Коды ссылок в базе хранятся хешами.

## Настройка в Render

Web Service: Build Command `pip install -r requirements.txt`, Start Command `python bot.py`, тариф Free.

Переменные окружения:

- `BOT_TOKEN` — токен от @BotFather;
- `DATABASE_URL` — Internal Database URL базы Render Postgres;
- `ADMIN_IDS` — Telegram ID администраторов через запятую (узнать свой ID: команда `/myid`).

При запуске бот создаёт таблицы и сам регистрирует вебхук на адрес сервиса (`RENDER_EXTERNAL_URL` + `/webhook`).

На бесплатном тарифе сервис засыпает после 15 минут без запросов, поэтому первое сообщение после паузы бот может обработать с задержкой около минуты. Бесплатная база Render удаляется через 30 дней после создания.
